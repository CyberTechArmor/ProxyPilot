# Public request refusal lifecycle

The owner authorized general public browsing in the selected runner through
review, CI, merge, application update, runtime installation and actual proof.

Independent source review found that gateway/supervisor ordinary public refusals
are per-request, but the worker freezes the entire attempt. One refused resource
then prevents further safe resources and transient pixel viewing. This source
finding does not establish the observed Python downloads failure's cause.

Align only well-formed trusted public block decisions with gateway semantics.
Preserve fatal budget/deadline/ledger/pause decisions, local protocol failures,
expired authority, fences, credentials, all-answer DNS and actual peer checks.
Never unfreeze an already frozen worker or bypass view's ticketed-document check.
Private agent behavior remains unchanged. No legacy demo generalization.

Real Chromium regressions must prove blocked POST has no upstream contact,
subsequent allowed GET and pixels work, blocked redirects never ticket the
destination, and fatal decisions still disable viewing. This is source evidence,
not installed-boundary acceptance. Deploy only after independent review/CI.

Dedicated post-update Install/Recover remain blocked by fresh authentication;
do not use Host Shell or another connector action as a substitute.
